# 答辩讲解稿（3分钟版）

## 开场（20秒）

各位老师好，我们组做的是《三国演义》企业级教学版 RAG 项目。  
项目目标是完成一个可运行、可验证、可扩展的最小闭环：文本切块、向量入库、语义检索、带引用回答。

---

## 一、项目做了什么（40秒）

我们的系统主要做四件事：

1. 对《三国演义》按章节和滑动窗口切块；
2. 为每个文本块生成向量并写入 Milvus；
3. 用户提问后做向量检索，召回最相关片段；
4. 基于召回片段生成答案，并返回引用来源。

这保证了答案不是“凭空生成”，而是可追溯、可解释。

---

## 二、现场演示怎么跑（50秒）

我只需要执行一条命令：

```bash
python main.py
```

启动时会自动完成三步：

- 检查并创建集合 `sanguo_chunks`；
- 如果集合为空，自动导入《三国演义》文本；
- 启动 FastAPI 服务。

然后我打开：

- `http://127.0.0.1:8008/health` 验证服务正常；
- `http://127.0.0.1:8008/docs` 在接口页演示 `POST /ask`。

---

## 三、如何证明数据真的进库了（35秒）

在 Attu 里，我们看到在 `default` 数据库下有集合 `sanguo_chunks`。  
集合字段包括：

- `id`：切片唯一标识；
- `chapter_no`、`chapter_title`：章节信息；
- `summary`、`content`：摘要与原文；
- `vector`：768维向量，带 HNSW(COSINE) 索引。

实体数量持续增长，说明入库与索引是成功的。

---

## 四、架构亮点（25秒）

代码按职责拆分：

- `chunking.py`：切块与摘要；
- `vector_store.py`：Milvus 建表、写入、检索；
- `pipeline.py`：串起导入和问答主流程；
- `api.py`：接口层；
- `main.py`：启动与自动导入。

这种结构比单脚本更接近真实工程，便于维护和扩展。

---

## 五、收尾（10秒）

总结：我们实现了一个可运行、可验证、可扩展的 RAG 教学闭环。  
下一步会接入真实 embedding、混合检索和 reranker，继续提升效果。
