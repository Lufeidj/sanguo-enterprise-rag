# 课程01：30分钟读懂你的 RAG 项目

## 本课目标

学完这一课，你要能独立回答三件事：

1. 请求从哪里进，在哪里被处理；
2. 数据如何从文本变成可检索向量；
3. 为什么 Attu 里看到的是集合 `sanguo_chunks`，而不是新数据库。

---

## 课前准备（2分钟）

- 服务启动：`python main.py`
- 打开接口页：`http://127.0.0.1:8008/docs`
- 打开健康检查：`http://127.0.0.1:8008/health`
- 打开 Attu 并定位 `default.sanguo_chunks`

---

## 第一部分：先看入口（8分钟）

### 1) `main.py` 看什么

- 调用 `bootstrap_data()`：确保集合可用，必要时自动导入；
- 调用 `uvicorn.run(...)`：启动 API 服务。

你要记住一句话：  
`main.py` = 启动器 + 初始化器。

### 2) `api.py` 看什么

- `GET /health`：服务心跳；
- `POST /ask`：接收问题并转到 `ask_question(...)`。

你要记住一句话：  
`api.py` 不做重逻辑，只做协议入口。

---

## 第二部分：核心数据链路（12分钟）

### 1) 入库链路：`pipeline.ingest_sanguo_file()`

流程是：

1. 读原文；
2. `build_chunks()` 切块；
3. `embed_texts()` 向量化；
4. 组装 rows；
5. `store.upsert(rows)` 入库。

### 2) 问答链路：`pipeline.ask_question()`

流程是：

1. 对问题向量化；
2. 向量检索 top_k；
3. 拼 `contexts` 和 `citations`；
4. `generate_answer(...)` 生成答案。

你要记住一句话：  
RAG 的关键不在“回答”，在“先检索再回答”。

---

## 第三部分：为什么是 collection 不是 database（5分钟）

在配置中：

- `MILVUS_DB_NAME=default`
- `MILVUS_COLLECTION=sanguo_chunks`

所以系统默认行为是：

- 进入 `default` 数据库；
- 创建/使用集合 `sanguo_chunks`；
- 不主动新建数据库。

---

## 课堂练习（3分钟）

请你自己完成以下动作并口述结果：

1. 在 `/docs` 发一个 `POST /ask` 问题；
2. 说出返回体里 `answer` 和 `citations` 的区别；
3. 在 Attu 里指出 `vector` 字段和索引类型；
4. 用一句话解释 `0.0.0.0` 与 `127.0.0.1` 的区别。

---

## 课后作业（可选）

1. 把 `AUTO_INGEST_ON_STARTUP` 设为 `false`，观察启动日志变化；
2. 修改 `top_k` 为 3 和 10，比较返回引用差异；
3. 准备一个你自己的答辩问题并完成一次完整演示。
