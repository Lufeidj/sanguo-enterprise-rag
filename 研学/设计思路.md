# 设计思路

## 1. 业务目标

构建一个“可演示、可落地、可扩展”的《三国演义》知识问答系统，满足：

- 能把长文本稳定入库
- 能根据问题召回相关知识片段
- 能生成可解释回答（带引用）

## 2. 核心思路

### 2.1 先保证流程闭环，再追求模型效果

先做通：
读取文本 -> 切块 -> 入库 -> 检索 -> 回答 -> 引用回传

在闭环可用的前提下，再逐步优化模型与检索质量。

### 2.2 章节优先切块

《三国演义》属于强叙事长文本，直接固定切块容易割裂语义。

因此采用：
1. 章节切分（第X回）
2. 章节内滑窗细分（带 overlap）

这样在保证召回粒度的同时，减少剧情断裂。

### 2.3 元数据驱动检索可解释

每个 chunk 存储：
- `chapter_no`
- `chapter_title`
- `summary`
- `content`

检索后将这些元数据回传给前端，便于答辩时展示“回答来源”。

### 2.4 一键运行体验

通过 `main.py` 实现自动引导：
- 自动检查/创建集合
- 集合为空时自动导入
- 自动启动 API

减少手工步骤，提升可演示性与可复现性。

## 3. 演进路线

第一阶段（当前）：
- 向量检索 + 基础生成

第二阶段：
- 接入 reranker，提升召回排序质量

第三阶段：
- 引入实体关系抽取，升级到 GraphRAG

第四阶段：
- 增加评测集与自动评估，形成工程闭环
