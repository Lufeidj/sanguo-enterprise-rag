# 《三国演义》企业级 RAG 演示项目 — 端到端流程详解（小白版）

本文假设你刚接触本项目，按**时间顺序**把「从什么都没有」到「浏览器里能问三国」的整条链路说清楚。涉及的代码路径以仓库根目录为准。

---

## 一、这个项目在做什么（一句话）

把《三国演义》长文本**切成小块**，给每块算**向量**，存进 **Milvus**；用户提问时，用**向量检索 + BM25 关键词检索**找回相关片段，**融合排序**后（可选再**语义重排**），把片段当**证据**交给大模型（或教学回退逻辑）生成**带引用**的答案。

---

## 二、你会用到的概念（先扫一眼）

| 概念 | 通俗理解 |
|------|-----------|
| **Chunk（切片）** | 书太长，切成几百字一段，每一段有 id、第几回、标题、摘要、正文 |
| **Embedding（向量）** | 把文字变成一串数字；意思相近的文字，数字空间里也离得近 |
| **Milvus** | 向量数据库，专门做「给向量，找最像的若干条」 |
| **BM25** | 经典关键词打分：问题里的词在段落里出现得是否「又准又稀有」 |
| **RRF 融合** | 把「向量排的队」和「BM25 排的队」合成一个分数，两路优点都要 |
| **Rerank（语义重排）** | 融合后再用向量算一遍「问题和段落有多像」，微调顺序 |
| **RAG** | Retrieval-Augmented Generation：先检索证据，再生成答案 |

---

## 三、运行前：你的电脑上要有什么

1. **Python 3.10+**（与 `requirements.txt` 一致即可）
2. **本仓库代码**克隆到本地
3. **Milvus 已启动**（教学常用 Docker：`milvus-standalone` 等，监听例如 `127.0.0.1:19530`）
4. **可选**：《三国演义》原文路径。默认配置指向课程 Day08 目录下的 txt；若没有，需自己改 `src/config.py` 里的 `DEFAULT_SANGUO_PATH` 或把书放到对应路径

---

## 四、配置：`.env` 在干什么

项目启动时会加载项目根目录的 `.env`（见 `src/config.py` 的 `load_dotenv`）。可复制 `.env.example` 为 `.env` 再改。

**和 Milvus 相关**

- `MILVUS_URI`：例如 `http://127.0.0.1:19530`
- `MILVUS_DB_NAME`：一般为 `default`
- `MILVUS_COLLECTION`：集合名，默认 `sanguo_chunks`

**和向量维度相关（非常重要）**

- `EMBEDDING_DIM`：必须和 embedding 模型输出维度一致。例如 DashScope `text-embedding-v4` 常用 **1024**。若用教学 mock 向量，维度也要和建表时一致；换模型后通常要**删集合重建**再导入。

**和 API 相关**

- `API_HOST` / `API_PORT`：服务监听地址与端口，默认 `0.0.0.0:8008`

**和 Embedding 服务相关（可选）**

- `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`：配全则入库与查询走**真实向量**；不配或失败则走 **mock 向量**（可复现的伪随机，见 `src/llm.py`）

**和对话模型相关（可选）**

- `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`：配全则 `/ask` 走真实大模型；不配则返回**教学模式拼接答案**（仍能演示检索与引用）

**和检索策略相关**

- `RECALL_TOP_K`：请求体里**未传** `recall_top_k` 时，召回阶段用的默认候选规模
- `VECTOR_RRF_K`、`KEYWORD_RRF_K`：RRF 公式里的常数，越大融合曲线越「平」
- `ENABLE_RERANKER`：是否做语义重排（HTTP API 未暴露该开关时，以环境变量为准；评测脚本可单独传参覆盖）
- `RERANK_CANDIDATE_CAP`：重排时最多对多少条候选做文档 embedding，防止太慢

## 五、阶段 A：准备向量库（不启动网页也能做）

### A1. 安装依赖

在项目根目录执行：

```bash
pip install -r requirements.txt
```

### A2. 初始化集合：`scripts/vdb_init.py`

**只做建表（集合不存在则创建，有索引）**

```bash
python scripts/vdb_init.py
```

**若集合为空，则尝试按默认路径导入《三国演义》**

```bash
python scripts/vdb_init.py --ingest
```

**强制再导一遍（会再次 insert，适合重建实验；生产慎用）**

```bash
python scripts/vdb_init.py --force-ingest
```

内部逻辑摘要：

- `SanguoVectorStore.ensure_collection()`：没有 `sanguo_chunks` 就按 schema 创建，向量字段维度为 `EMBEDDING_DIM`，索引类型 **HNSW**，距离 **COSINE**（见 `src/vector_store.py`）
- `--ingest`：`bootstrap_data` 发现行数为 0 且文本存在时调用 `ingest_sanguo_file`

### A3. 入库主流程：`ingest_sanguo_file`（`src/pipeline.py`）

1. **读文件**：UTF-8 读入整本书字符串  
2. **切块**：`build_chunks(text)`（`src/chunking.py`）  
3. **向量化**：`embed_texts([每块 content])`（`src/llm.py`）  
4. **写 Milvus**：每行包含 `id, chapter_no, chapter_title, summary, content, vector`  
5. **flush**：写入后 flush，保证行数统计与检索可见（`vector_store.upsert`）

### A4. 切块策略：`src/chunking.py`（你要能复述）

1. **按回目切大段**：正则匹配「第……回……」作为章节标题，中间正文归到该回  
2. **章内滑动窗口**：默认每段最多约 **800** 字，相邻段重叠约 **160** 字，减少切断情节  
3. **chunk_id**：例如第 1 回第 3 段 → `ch001_003`  
4. **summary**：教学版用首句截断，不是 LLM 摘要

## 六、阶段 B：启动 API 与前端

### B1. 启动命令

```bash
python main.py
```

`main.py` **只负责**用 Uvicorn 启动 FastAPI 应用，**不再**自动做向量库导入（与早期单文件脚本习惯分离）。

### B2. FastAPI 应用：`src/api.py`

- `GET /health`：返回 `{"ok": true}`，探活  
- `POST /ask`：请求体见 `src/schemas.py` 的 `AskRequest`  
  - `question`：用户问题  
  - `top_k`：最终进入上下文、作为引用的条数（默认 5，上限 20）  
  - `recall_top_k`：可选；召回阶段向量路与 BM25 路各取多少候选（与 `top_k` 取 max 作为 `recall_k`）  
- `GET /`：返回 `web/index.html`  
- `/web/...`：静态资源挂载

版本号在 `FastAPI(..., version="0.1.0")` 中，与 Git 标签可对应。

## 七、阶段 C：一次问答在代码里怎么走（核心）

入口：`ask_question`（`src/pipeline.py`），由 `POST /ask` 调用。

### C1. 问题向量化

- `embed_query(question)` → 与入库同一套逻辑（真实 API 或 mock）

### C2. 双路召回（Recall）

- **向量路**：`store.search(q_vec, top_k=recall_k)`，Milvus 近似最近邻  
- **关键词路**：`BM25Retriever.search(store, question, top_k=recall_k)`  
  - BM25 索引在内存：从 Milvus **query 出全部 chunk 文本**，在进程内建词频与 IDF（见 `src/retrieval.py`）  
  - 行数变化时会自动重建索引

`recall_k = max(top_k, recall_top_k 或 RECALL_TOP_K)`，保证召回宽度不小于最终条数。

### C3. RRF 融合（`_hybrid_rerank`）

- 给每个 chunk id 记下：**在向量结果里的名次**、**在 BM25 结果里的名次**（没出现的那一路用较大默认名次）  
- 分数形如：`1/(VECTOR_RRF_K + 向量名次) + 1/(KEYWORD_RRF_K + BM25名次)`  
- 按分数排序得到 `fused_hits`，并写入 `hybrid_score` 供展示与重排池排序

### C4. 语义重排（可选）

- 若 `ENABLE_RERANKER` 为真（且调用方未传 `enable_reranker=False`）：`semantic_rerank(question, fused_hits, top_n=top_k)`（`src/reranker.py`）  
  - 只对融合分最高的前 `RERANK_CANDIDATE_CAP` 条（至少 `top_n`）做文档 embedding，再与问题向量算余弦相似度，与 `hybrid_score` 加权得到 `rerank_score`  
- 否则：直接 `fused_hits[:top_k]`

### C5. 拼上下文与引用

- 对最终每条 hit，截取 `content` 前 500 字拼进 `contexts` 列表（给模型读）  
- 同时构造 `Citation`：含 `chunk_id`、回目、标题、`score`（优先 `rerank_score`，否则 `hybrid_score` 等）、正文前 240 字（给前端展示）

### C6. 生成答案

- `generate_answer(question, contexts)`（`src/llm.py`）  
  - 无 LLM 配置：固定模板 + 截取上下文 → **教学模式**  
  - 有配置：OpenAI 兼容 `chat.completions`；异常时仍回退教学模式

### C7. 返回

- `AskResponse`：`answer` + `citations`

## 十、常见问题（小白向）

**Q：改 embedding 模型后检索很怪？**  
A：维度必须等于 `EMBEDDING_DIM`；旧向量与新模型不在同一空间，需要**删集合 + 重建 + 全量重导**。

**Q：Attu 里看不到数据？**  
A：确认导入成功、`flush` 已执行；数据库选 `default`，集合名与 `MILVUS_COLLECTION` 一致。

**Q：`recall_top_k` 和 `top_k` 区别？**  
A：`recall_top_k` 管「两路检索各捞多少候选」；`top_k` 管「融合（及可选重排）后真正给模型几条」。

**Q：为什么评测里关 rerank 有时更好？**  
A：当前语义重排是轻量实现，且评测指标偏关键词命中与延迟；线上可按业务再调权重或换交叉编码器重排。
